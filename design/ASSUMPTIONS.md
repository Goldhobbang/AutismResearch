# ESP32-S3 설계 가정·에너지 시나리오

2026-10-23 사용자 구상 반영. L3 계산이며 실측이 아니다. 현행 범위는 BLE-only다. Mic/Light를 포함한 새 구조로 계산 예를 변경했다.

`Iavg = Σ(배터리측 등가전류 × duty)`, `life_h = capacity_mAh × usable_fraction / Iavg_mA`.

서로 다른 전압 rail의 전류를 그대로 더하지 않고 모두 배터리측 등가전류라는 가정으로 정의한다. 실제로는 rail전력·regulator효율을 적용해야 한다. 유효용량80%도 온도·열화·차단·편차를 묶은 가정이다.

| 항목 | 임의 가정 | 평균 기여 |
|---|---|---:|
| PPG | 연속4mA | 4.000mA |
| EDA AFE | 연속0.3mA | 0.300mA |
| IMU | 연속0.1mA | 0.100mA |
| Mic | 연속0.65mA | 0.650mA |
| Light | 평균0.05mA | 0.050mA |
| 전원·기타 | 평균0.5mA | 0.500mA |
| MCU | 15초마다1초35mA, 나머지3mA | 5.133mA |
| BLE | 1초마다10ms 추가8mA | 0.080mA |
| 선택진동 | 하루10회×2초×60mA | 0.0139mA |

이 전류는 **특정 ESP32-S3 보드·센서의 데이터시트 보장값이 아니다.** MCU1초는 추론/특징 시간을 측정한 값이 아니며 3mA 대기는 deep-sleep 실측값이 아니다. BLE event와 MCU 전류의 중복 계상이 없는 모델인지 실제 전력 추적으로 확인해야 한다. 진동은 기본 비활성 제안이며 표의 횟수는 비교용 가정이다.

PPG1/4/10mA와 셀150/300mAh를 조합한 민감도 표를 `energy_scenarios.csv`에 제공한다. 기본 예는 약10.83mA,150mAh×80%에서 약11.08h다. 실제 수명·충전 주기 보장이 아니다. 개발보드 LED·USB bridge·LDO·마이크·RF 부하·센서 설정에 따라 크게 달라진다. 피크 전류·셀 안정성·발열은 평균 계산만으로 확인되지 않는다.

재현: `py design/energy_budget.py`. 실제 전력분석·셀/충전 시험과 분리한다. 선택한150mAh 셀의 판매자는 충전150mA 이하를 명시하므로, 충전기의 기본값이 이보다 높다면 그대로 연결하지 않는다. 최종 셀/충전회로는 아직 미정이다.
